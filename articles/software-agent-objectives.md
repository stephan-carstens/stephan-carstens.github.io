I regularly and repeatedly struggle to get llm agents to generate software that is of high quality. After some (very little) thought, I have arrived on the hypothesis that it is
at least in part because software is so open. There is no verifiable reward/ difference in arriving at a "correct' technical solution to a problem vs. hacking your
way to it. If the task is to get requirement A implemented, then requirement A could be implemented in a myriad of ways. 

Of course your LLMs is unlikely to use
brainfuck or assembly to write a solution if the code up till now has been in python, but leaving holes is not penalised as long as the current objective is satisfied. There is no downside to this from the agent's
perspective. It has no concept of maintenance costs, the cost of wrong code versus introducing no the mental damage it is inflicting on its users because of its inability to communicate (Can you just speak like a normal person?). 


It makes me think of a optimization problem where some
penalty terms are missing.

Software Engineers are very aware of the reality of the ground shifting underneath us and we have therefore come up with all kinds of tricks to increase openness to change.
